## 1. Model Details（模型基本信息）

| 项 | 内容 |
|---|---|
| 系统名称 | **MetricForge** |
| 包名 | `metricforge` |
| 仓库 | `cjx0712/metricforge` |
| 任务类型 | 度量学习 / 对比表征学习（**向量输入**，非原始图像） |
| 学习范式 | 监督度量学习 + 可选局部几何正则；无自监督预训练 |
| Encoder | 纯 numpy 手写 MLP（Tier-1）；可选 torch MLP（Tier-0） |
| 嵌入维度 | dim_out=12（fast 档 demo 配置；线性方法自动裁剪至 ≤ 输入维） |
| 可训练参数量 | 随数据集维度变化（MLP d→h→D，h≤64），典型数千~数万级 |
| 主损失 | $\mathcal{L}_{\text{Forge}} = \mathcal{L}_{\text{MQ-BPA}}^{\tau_{\text{HAT}}} + \lambda_{\text{geom}}\mathcal{L}_{\text{geom}} + \lambda_{\text{lb}}\mathcal{L}_{\text{lb}}$ |
| 自研组件 | **HAT**（Hardness-Adaptive Temperature）、**MQ-BPA**（Memory-Queue Bi-directional Proxy Alignment） |
| 运行时依赖（必需） | `numpy` + `scipy` + `scikit-learn`（合计 57.4 MB wheel，零编译、零下载数据） |
| 运行时依赖（可选） | `torch`（Tier-0 交叉验证）、`metric-learn` + shim（oracle）、`pytorch-metric-learning`（参考）—— 三者均 `try/except` 探测，缺失 skip |
| 硬件要求 | CPU-only（AMD64）。**不要求 GPU，也不使用 GPU** |
| 代码许可 | MIT License（© 晨星） |
| 模型权重许可 | MIT License（无预训练权重，模型即代码） |

## 2. Intended Use（预期用途）

### 2.1 预期用途（适用）

| 场景 | 说明 |
|---|---|
| **小/中等规模向量数据的度量学习** | 输入为已特征化的向量（表格特征、embedding、TF-IDF 等），学习一个更适合最近邻检索/聚类的嵌入空间 |
| **最近邻检索与语义去重** | 学习后的嵌入用于 kNN 检索、近重复检测、"更多类似项"推荐 |
| **小样本表格数据的嵌入学习** | 尤其类数较多、类内存在多模态（子类）结构时 |
| **算法研究与教学** | 全部损失函数、采样器、指标均为可读的纯 numpy 实现，可逐步对照公式验证 |
| **离线/无网环境** | 不下载任何预训练权重或数据集即可完整运行 |

### 2.2 不适用场景（Out-of-Scope，**明确列出**）

| # | 不适用场景 | 原因 |
|---|---|---|
| **O1** | **需要 ImageNet 预训练视觉 backbone 的图像检索**（如 CUB-200-2011 / Cars196 / Stanford Online Products / In-shop Clothes 上的 R@1 竞赛） | 本系统**输入是向量而非原始图像**，encoder 为**随机初始化小 MLP**，无预训练权重、无 GPU。这些 benchmark 上的 SOTA（ViT 系 R@1 85–89）依赖 ImageNet 预训练 + GPU 训练数小时，与本系统不在同一任务层。**详见 `docs/related_work.md` 文末专节。** |
| **O2** | **超出 CPU-only 预算的规模** | 设计规格为单次 `fit` ≤ 60 s、peak RSS ≤ 2 GB（见 §5-L3 的规模上限讨论）。超出该预算的数据规模不在支持范围内。 |
| **O3** | **时序 / 序列 / 流式数据** | 本系统不含任何时间维度建模，也不提供滑窗、在线更新、概念漂移处理。 |
| **O4** | **生产级身份识别与生物特征验证**（人脸、声纹、指纹） | 未做公平性评估、未做跨域/跨 demographic 分组评测、未做对抗鲁棒性测试。**禁止**用于身份验证、安防、执法等场景。 |
| **O5** | **医疗、司法、信贷等高风险决策** | 未经过任何监管合规评估。B 组数据中的 `breast_cancer` 仅作公开基准用途（见 §3.4）。 |
| **O6** | **需要在线下载权重/数据的部署环境** | 虽然本系统本身零下载，但若配置里启用了 `--online` 数据分支或 Tier-0 torch 后端，则该部署前提不再成立。 |
| **O7** | **开放世界的大规模向量数据库检索**（千万级以上） | 未提供 ANN 索引（HNSW / IVF-PQ）与分布式检索能力。 |

### 2.3 误用风险提示

- 用本系统在 **O1 类图像 benchmark 上刷分并对外宣称"达到 SOTA"** 属于严重误用。本卡的 §4 与 `related_work.md` 已固定对标口径，**不得改写**。
- 把 §5 的**局限**当作"已解决的问题"引用，同样属于误用。

## 3. Training Data（训练数据）

全部训练数据分三组：**A 组合成可控**、**B 组真实小规模（离线内置）**、**C 组真实（需联网，可选）**。

### 3.1 A 组：合成可控数据（S1–S6）

由 `metricforge/data/synth.py` 生成，**完全由 seed 决定，不含任何真实世界采样**。设计意图是提供**已知 ground-truth 结构**的可控难度阶梯。

| ID | 名称 | 生成方式与分布假设 | 规模 / 维数 / 类数 | 设计意图 | 关键可调参数 |
|---|---|---|---|---|---|
| **S1** | `gauss_blobs` | $C$ 个**各向异性高斯团**，各类单一模态 | $N{=}4000,\ d{=}32,\ C{=}16$ | 标准单模态基线；欧氏 kNN 在此已很强，用作"打不过就别吹"的饱和检查 | 团间 Mahalanobis 间距 $\Delta$（默认 2.0） |
| **S2** | `concentric` | 2–4 个**同心环** + 角度/半径扰动 | $N{=}3000,\ d{=}2$ | **欧氏距离结构性失败**的教科书案例 | 环间距、噪声 |
| **S3** | `spirals` | 三**螺旋**，参数化弧长 + 高斯噪声 | $N{=}3000,\ d{=}2$ | 需要高度非线性度量（线性 Mahalanobis 必败） | 圈数、噪声 |
| **S4** | `subspace` | 每类落在一个随机 $d_{sub}$ 维**线性子空间** + 各向同性噪声 | $N{=}5000,\ d{=}200,\ C{=}50,\ d_{sub}{=}8$ | 高维稀疏、类数多；检验负样本池与 proxy 的扩展性 | $d,\ d_{sub},\ C$, SNR |
| **S5** | `xor_grid` | **棋盘 / XOR 分块**均匀分布 | $N{=}2000,\ d{=}2$ | 线性 Mahalanobis **必然失败** | 块数 |
| **S6** | `hier_gauss` | **层次化**：每大类含 2–3 个分离子类团（类内多模态） | $N{=}4500,\ d{=}32,\ C{=}15$（约 45 子团） | **多原型（$K{>}1$）的主判别集** | 子类间距 / 大类间距之比 $\rho$ |

**分布假设的诚实说明**：这些生成器的类别结构（尤其是"类 = 单个高斯团"或"类 = 单个线性子空间"）是**人为设定**的，真实数据往往不满足。因此**合成集上的优异表现不能直接外推到真实数据**——这也是 §4 要求结果表必须**分开报告**合成集与真实集的原因。

| ID | 数据集 | 规模 / 维数 / 类数 | 来源 | 许可状态 |

| **R1** | `load_digits` | 1797 × 64，10 类 | scikit-learn 内置（源自 UCI 手写数字集的预处理版本） | {{TODO: 由主理人在发布前确认各数据集原始许可条款}} |

### 3.3 C 组：可选数据（需显式 `--online`）

`fetch_openml`（如 `segment` / `glass` / `vehicle` / `vowel` / `letter`）、UCI 小型集、20newsgroups + TF-IDF。

**规则**：
- 默认**不加载**，必须显式传 `--online`。
- 结果只能进附录，且须在表格中标注 `network=required`。
- **CI 与 demo 不得依赖 C 组**，否则违反"零下载可跑"的硬约束。

### 3.4 数据合规与伦理声明

- A 组合成数据不含任何真实个人数据，无隐私问题。
- B 组均为**公开学术基准集**，已去标识化，规模极小，仅用于算法评测。
- **R3（breast_cancer）为医疗相关基准数据**，仅作公开的二分类度量学习评测用途。**本系统不是医疗器件，不得用于任何诊断、筛查或临床决策。**
- 本系统**不使用**任何需要下载的真实用户数据、抓取数据或受保护数据。

### 3.5 数据划分与无泄漏

见 `docs/algorithm_design.md` §4.2。要点：
- 主协议为 **P2 open-set（类不相交）**：前半类 train+val，后半类 test。
- `StandardScaler` / PCA **只在 train 上 fit**。
- 所有超参**只在 val 上选**；**每个方法每个数据集只允许用 test 一次**。
- 这些约束均有单测断言守护。

## 5. Limitations（局限）

### L1 — κ 敏感性（**条件启用**）

HAT 的参与率目标 $\kappa$ 默认取 **0.25**，该值是**启发式选取**，未经过跨数据集的稳定性验证。

- **启用条件**：消融 A8（$\kappa \in \{0.15, 0.25, 0.40\} \times \{$S1, S6, S4$\}$）实测 ΔMAP@R 的**极差 > 0.02**。
- **启用后的处置**：在本卡与 model card 局限章节写明，并列入 v1.1 roadmap 的 adaptive-κ。
- **本轮不做**：自适应 κ 的实现（会破坏逐位确定性的论证成本过高，性价比不足）。

状态：**未触发**：A8 κ 敏感性极差 ≤ 0.02，默认 κ=0.25 在实测范围内稳健，无需启用 adaptive-κ。

### L2 — 小样本低维表格集上，线性 Mahalanobis 方法可能不输深度对比法

在类别边界简单、样本少、维度低的表格数据上（如 R2 wine / R3 breast_cancer / R4 iris），**线性方法（LMNN / LFDA / NCA）常常持平甚至优于深度对比方法**。这与 Rabbani, Medri & Samad (*Int. J. Data Sci. Anal.*, 2025, DOI 10.1007/s41060-024-00681-z) 在 28 个表格数据集上的数据中心基准结论一致：_"traditional methods are frequently superior on easy data sets with presumably simpler decision boundaries"_。

- MetricForge 的**预期优势域**是：类别多、类内多模态（层次化子类）、维度高、batch 相对类数偏小。
- **这是可证伪预测，不是既成结论**：若实测不支持，须按方案 §6 拍板 2 如实写入失败章节，不得通过换数据集、改指标、加 seed 数来规避。

实测结论：在 tiny open-set 协议下，kNN 原始空间与线性方法（LFDA/LMNN）即构成强天花板；MetricForge 与最强深度基线（Triplet-BH / Proxy-Anchor / SupCon）在噪声范围内持平，未发现 ≥+0.03 的显著优势（见 §4.3 G1/G3 实测口径）。这是可证伪的诚实结论：提升方向列入 v1.1 roadmap——更大数据集、closed-set 协议对照、更强 hard-mining 与encoder 预训练，而非在本协议内继续调参。

### L3 — CPU-only 规模上限

本系统**不使用 GPU**，也不提供任何 GPU 加速路径。由此带来的规模上限：

| 约束 | 值 | 性质 |
|---|---|---|
| 单次 `fit` 墙钟 | ≤ 60 s | 设计规格 |
| peak RSS | ≤ 2 GB | 设计规格 |
| 主瓶颈 | Fresh-Queue 每步重新前向 $O(M\,d\,h)$ 与相似度矩阵 $O(BMD)$ | 已知瓶颈 |
| 可承载的最大 $N$ / $d$ / $C$ | {{TODO: 由主理人填入实测外推}} | 待实测 |

已知的工程约束：**禁止物化全局 $N \times N$ 相似度/距离矩阵**，必须分块。即使如此，样本数增长到万级、维数增长到千级后，CPU 预算会先于内存预算耗尽。

### L4 — 其他已知局限（补充）

1. **合成数据外推风险**：A 组的类结构是人为设定的（见 §3.1），合成集表现不能直接外推到真实数据。
2. **统计强度有限**：3 seeds + bootstrap CI 只能给"**方向性证据**"，**不构成 $p<0.05$ 的统计显著结论**。报告措辞固定为此，不得升级。
3. **超参只在固定预算下搜索**：每方法每数据集固定 24 次随机搜索。更强的调参预算可能改变相对排序（这也是 Musgrave et al. ECCV 2020 指出的复现性风险之一）。
4. **无自监督预训练路径**：本系统不从无标签数据中学习通用表征，伪标签自训练仅列为可选扩展，未在本次范围内实现与评测。
5. **无公平性/鲁棒性评估**：未做跨子群性能差异测试、未做对抗鲁棒性测试。见 §2.2 O4/O5。

## 6. 伦理与复现性声明

### 6.1 种子协议

- **唯一 seed 入口**：`metricforge.set_seed(s)`。所有随机性（数据划分、参数初始化、batch 顺序、合成数据生成、dropout 等）必须经由该入口派生的 `random.Random` / `numpy.Generator` 实例。
- **禁止**裸 `np.random.*` 全局调用与 Python 内置 `hash()` 派生种子（后者在部分场景下受 `PYTHONHASHSEED` 影响，可审计性差）。
- 报告 seed 集：$\{0, 1, 2\}$（≥3）。
- 外部环境变量 `PYTHONHASHSEED` 需固定。

### 6.2 确定性保证范围（**明确边界**）

| 保证 | 范围 | 例外 |
|---|---|---|
| **同 seed 两次运行核心指标逐位一致**（I10） | ✅ 保证。同版本、同机器、同依赖版本下，两次 `fit` 的嵌入矩阵 `np.array_equal` 为 True，MAP@R 差 $= 0.0$ | — |
| **跨依赖版本一致** | ❌ **不保证**。numpy / BLAS 版本变化可能改变浮点求和顺序 | 属已知边界 |
| **跨机器 / 跨 CPU 一致** | ❌ **不保证**。不同 BLAS / SIMD 指令集可能有 ULP 级差异 | 属已知边界 |
| **多线程归约顺序** | ⚠️ 需通过固定线程数（`OMP_NUM_THREADS` 等）约束 | 未固定则不保证 |
| **HAT 二分迭代次数** | 固定常数（默认 40），**禁止**改用 while 收敛判据 | 否则 I10 直接失效 |

> 逐位确定性是本系统最硬的卖点之一，但**只在同一环境内成立**。对外宣传时不得表述为"跨平台可复现"。

### 6.3 伦理声明

- 本系统为**通用度量学习算法实现**，不含针对特定人群的特征工程。
- **未做**公平性评估（跨 demographic 子群的性能差异）、**未做**对抗鲁棒性测试、**未做**隐私攻击（成员推断 / 属性推断）评估。
- 训练数据均为公开学术基准或合成数据（§3.4）。
- **禁止**用于生物特征身份识别、执法、信贷、医疗诊断等高风险决策（§2.2 O4/O5）。

### 6.4 复现步骤

```bash
# 1. 环境（Tier-1 三件套，57.4 MB，零编译）
pip install numpy==2.5.3 scipy==1.18.1 scikit-learn==1.9.1

# 2. 冒烟（≤60s，零下载）
python -m metricforge.demo --profile fast --seed 0

# 3. 不变量单测（Release-blocking）
python -m pytest tests/test_invariants_core.py -v

# 4. 全量 benchmark（6 数据 × 7 方法 × 3 seeds）
python -m metricforge.bench.run --seeds 0,1,2 --protocol open-set

# 5. 消融
python -m metricforge.bench.ablation --ablation A1,A2,A3,A4,A5,A6,A7,A8
```

确定性核验：连续执行两次步骤 4，比对输出 CSV 的 MAP@R 列，差值必须为 `0.0`。
